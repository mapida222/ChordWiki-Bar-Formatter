# 更新履歴のコンパクト表示 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 日付をまとめ、最大360pxのパネル内で履歴を自動追加する。

**Architecture:** 本文・日付・カテゴリ名・順番を保ち、日付別section内に見出しと履歴リストを置く。HTML自体に日付を1回だけ記載し、JavaScript未実行でも重複させない。既存の5件単位の表示処理をスクロール・開閉・リサイズに接続し、表示項目のない日付グループも非表示にする。

**Tech Stack:** 既存のHTML、CSS Grid、素のJavaScript、Node標準テスト、Vite。

**Spec:** このチャットの「更新履歴の表示レイアウト改善」依頼（追記後）。

## Global Constraints

- 本文・日付・カテゴリ・並び順を変更しない。
- カテゴリの配色と角丸背景、ライト／ダークテーマを維持する。
- 日付13px、カテゴリ11px、本文13〜14px。カテゴリと本文は固定幅の2列。
- ボタンを廃止し、全件表示時のみ「すべての更新履歴を表示しました」を表示する。
- 新規依存関係や保存形式の変更、公開は含まない。

## Review Focus

- 初期5件だけでスクロールできない場合も、開いたときに補充できる。
- 追加境界が同日の途中でも日付が重複しない。
- 最終バッチが5件未満でも重複・欠落がなく、完了状態が伝わる。
- スクロール位置と背面のページ位置を保持する。
- 390px幅・両テーマで折り返し、本文開始位置、コントラストを確認する。

## CSSのみの表示で位置が戻る問題への対応

- JavaScriptを除いた一時検証ページで、通常CSSの`top: calc(100% + 6px)`が下段ボタンまで含めて配置する症状を再現。バーとの間隔は約45pxで、ボタンに重なっていなかった。
- バーの高さ36pxをCSS変数で共有し、通常CSSでもその直下へ出すよう変更。JavaScriptによる実寸補正も残す。
- スクリプト0本のページでもPC・390px・320pxでボタンとの重なりを確認。通常ページはバーとの間隔6pxを確認。
- ローカルの旧CSSが残らないよう、index.htmlのCSSキャッシュバスターを更新。
